# AccountantBot

Первоначальный каркас финансового бота для беседы ВКонтакте. Приложение целиком написано на Rust, получает события через VK Bot Long Poll и хранит данные в SQLite.

## Что уже есть

- команды принимаются от участников беседы, в которую добавлено сообщество;
- бот откликается на имя `Зая` без учёта регистра; команды можно писать как `Зая баланс` или в прежнем виде `Баланс`;
- команды `Начальный остаток`, `Доход`/`Приход`, `Расход`, `Баланс`, `Расходы`, `История`, `Отмена`;
- каждая беседа имеет собственный баланс, историю и отчёты, разделённые по её `peer_id`;
- отрицательный остаток разрешён;
- категории регистронезависимы;
- отмена ответом на сообщение или отмена последней своей операции;
- после дохода или расхода показывается текущий остаток и быстрые кнопки отчётов;
- `Расходы по группам` группирует расходы по категориям за 14, 30 дней или 3 месяца;
- `История расходов` показывает операции за 14, 30 дней или 3 месяца;
- активный период истории подсвечивается синим;
- `Бюджет по месяцам` отправляет PNG-диаграмму доходов и расходов по месяцам;
- защита баланса от повторной доставки одного события VK;
- inline-кнопки, SQLite, Docker Compose и скрипт резервного копирования.

Кнопки Excel формируют и отправляют файл с полной финансовой историей беседы: кто добавил операцию, дата, тип операции, приход, расход и остаточный баланс после операции. В сообщении с готовым XLSX отображается только кнопка `Текущий баланс`, без повторной кнопки экспорта. Клиентская база пока не реализована. Поле `ALLOWED_EXPENSE_CATEGORIES` позволяет включить фиксированный список категорий без изменения кода.

После команд `Доход` и `Расход`:

```text
[ История расходов | Расходы по группам ]
[          Бюджет по месяцам            ]
```

В разделе статей расходов:

```text
[          Баланс | Расходы          ]
[          Расходы по группам        ]
[          Бюджет по месяцам         ]
[          Выгрузить в Excel         ]
```

После нажатия «Расходы по группам»:

```text
[       14 дней | 30 дней              ]
[             3 месяца                 ]
[           Текущий баланс            ]
[  Выгрузить всю историю в Excel      ]
```

В истории расходов:

```text
[       14 дней | 30 дней              ]
[             3 месяца                 ]
[           Текущий баланс            ]
[  Выгрузить всю историю в Excel      ]
```

Выбранная кнопка периода (`14 дней`, `30 дней` или `3 месяца`) подсвечивается цветом `primary`. `Текущий баланс` работает как обычная команда `Баланс` и возвращает тот же экран.

Диаграмма «Бюджет по месяцам» охватывает текущий и три предыдущих месяца. Для каждого месяца рядом располагаются два столбца: зелёный — доходы, красный — расходы. Под каждой парой указаны месяц и двузначный год, например `август, 26`. Изображение генерируется приложением и загружается в сообщение VK.

В сводке за выбранный период расходы с одинаковой категорией объединяются, например две операции `Материалы` на 6 000 ₽ и 4 000 ₽ отображаются одной строкой `Материалы: 10 000 ₽`. Регистр в названии категории не учитывается.

## Тестовые данные

В текущем тестовом `.env` установлен `ENABLE_DEMO_DATA=true`. После запуска бота отправьте в нужной беседе скрытую команду:

```text
Тестовые данные
```

Бот добавит 11 демонстрационных доходов и расходов: за последние 14 и 30 дней, а также за один, два и три месяца назад. Заполнение идемпотентно — повторная команда не создаёт дублей. Данные добавляются именно в ту беседу, откуда отправлена команда, поскольку её `peer_id` заранее неизвестен.

Перед боевым запуском обязательно установите `ENABLE_DEMO_DATA=false`. Удалять демонстрационные операции из рабочей базы вручную не рекомендуется; для чистого запуска используйте новую базу.

## Настройка VK

1. Создайте или выберите сообщество VK и включите сообщения сообщества.
2. В настройках Long Poll API включите Long Poll и событие `Входящее сообщение`.
3. Создайте ключ доступа сообщества с правом на сообщения.
4. Разрешите добавлять сообщество в беседы, добавьте его в нужный чат и выдайте доступ ко всей переписке. Права администратора беседы также подходят.
5. Заполните локальный `.env`: токен и ID сообщества без минуса.

Не публикуйте `.env`: он уже добавлен в `.gitignore` и исключён из Docker build context.

## Локальный запуск

```bash
cargo test
cargo run
```

До заполнения `.env` приложение ожидаемо завершится с сообщением о placeholder-значении.

## Запуск в Docker

```bash
docker compose up -d --build
docker compose logs -f accountant-bot
```

База хранится на хосте в `data/accountant.db`, а не внутри контейнера. Это упрощает перенос и резервное копирование. При запуске entrypoint исправляет владельца каталога `data` для UID `10001`, после чего запускает приложение от непривилегированного пользователя `bot`. Благодаря этому bind mount работает на Linux VPS без ручного `chown`.

## Надёжная доставка ответов

Финансовая операция и исходящий ответ сохраняются в одной SQLite-транзакции. Отдельный outbox-обработчик отправляет сообщения и диаграммы в VK. Если VK временно недоступен или контейнер перезапущен, неотправленный ответ остаётся в таблице `outbox` и повторяется с увеличивающейся задержкой до успешной доставки.

Повторная отправка использует тот же `random_id`, поэтому авария между отправкой в VK и отметкой доставки не должна создавать второе сообщение.

## Диагностические и аналитические логи

Приложение пишет структурированные JSON-логи в stdout контейнера. Токен VK, полный текст сообщений, суммы и категории в логи не выводятся.

```bash
# Все логи в реальном времени
docker compose logs -f accountant-bot

# Последние 200 записей
docker compose logs --tail=200 accountant-bot

# Только ошибки
docker compose logs accountant-bot | grep '"level":"ERROR"'

# Периодические аналитические снимки
docker compose logs accountant-bot | grep 'application analytics snapshot'
```

Для каждой выполненной команды записываются её тип, ID события, беседы и автора, время обработки и размер ответа. Каждые `ANALYTICS_INTERVAL_SECONDS` секунд выводятся накопительные счётчики событий, выполненных команд, дублей, некорректных команд, переподключений и ошибок.

Настройки:

- `LOG_FORMAT=json` — JSON для Docker и систем сбора логов; другое значение включает компактный текст;
- `RUST_LOG=info,sqlx=warn,reqwest=warn` — уровень детализации;
- `ANALYTICS_INTERVAL_SECONDS=300` — интервал аналитического снимка.

Для временной углублённой диагностики можно установить `RUST_LOG=debug,sqlx=warn,reqwest=info` и перезапустить контейнер. Постоянно оставлять `debug` на VPS не рекомендуется из-за объёма логов.

Docker автоматически ротирует журнал: хранится до пяти файлов по 10 МБ, поэтому аналитика не должна бесконтрольно занять диск VPS.

## Проверка состояния VPS

Из корня проекта можно запустить комплексную диагностику сервера:

```bash
./scripts/check.sh
```

Скрипт по SSH проверяет доступность сервера, диск и память, Docker Compose, состояние и количество перезапусков контейнера, ошибки и переподключения в логах, соединение с VK Long Poll, целостность основной SQLite-базы, зависшие сообщения в `outbox`, systemd-таймер резервного копирования, свежесть и целостность последнего бэкапа.

Адрес сервера и каталог приложения берутся из локального `.env`, который не попадает в Git:

```dotenv
VPS_SSH_TARGET=user@server.example.com
VPS_APP_DIR=/opt/accountant-bot
```

Для разовой проверки другого сервера значения можно передать аргументами:

```bash
./scripts/check.sh root@example.com /opt/accountant-bot
```

В терминале успешные проверки отмечаются зелёным `✓`, предупреждения — оранжевым `⚠`, критические ошибки — красным `✗`. При перенаправлении вывода и запуске из cron цвета автоматически отключаются. Коды возврата подходят для автоматического мониторинга: `0` — всё хорошо, `1` — есть предупреждения, `2` — критическая ошибка. Дополнительные настройки перечислены в `./scripts/check.sh --help`.

## Развёртывание на VPS

На сервере создайте отдельный каталог, например `/opt/accountant-bot`, скопируйте туда проект и заполненный `.env`, затем выполните:

```bash
docker compose up -d --build
docker compose ps
```

Существующий бот не затрагивается: у нового приложения отдельные контейнер, имя, переменные и база. Для переноса сначала остановите старую копию, скопируйте каталог с базой, затем запустите новую — две копии одновременно запускать нельзя.

## Резервная копия

На хосте должен быть установлен `sqlite3`:

```bash
./scripts/backup.sh
```

Скрипт использует безопасную команду SQLite `.backup` и кладёт снимок в `backups/`. Для регулярного запуска добавьте его в cron на VPS. Проверять восстановление нужно на отдельной копии файла.

На VPS systemd-таймер из `deploy/systemd` запускает резервное копирование ежедневно в 05:15 по московскому времени. Проверить его можно командами:

```bash
systemctl status accountant-bot-backup.timer
journalctl -u accountant-bot-backup.service -n 50
```

## Формат команд

```text
Зая
Зая начальный остаток 50000
Зая доход 15000
Зая расход Расходные материалы 4000
Зая баланс
Зая расходы по группам
Зая история расходов
Зая бюджет по месяцам
Зая отмена
```

Имя `Зая` регистронезависимо: `Зая`, `зая` и `ЗАЯ` работают одинаково. Старые команды без обращения также поддерживаются, а кнопки работают как раньше. Суммы — положительные целые рубли. Обычные сообщения беседы бот игнорирует.
